# n8nitro SimplePractice2 Sync

Choosing to Speak gets its daily clinical context from a duplicate of the existing n8nitro/reMarkable planner pipeline. The duplicate keeps the existing `SimplePractice2`, Notion, and OpenRouter prep nodes, then normalizes the final payload and posts directly to the Choosing backend.

## Runtime Flow

1. n8nitro runs `Choosing to Speak — SimplePractice2 Context Sync`.
2. The workflow reads the authoritative `SimplePractice2` Google subcalendar.
3. The workflow enriches each session from the existing Notion client database map.
4. The workflow asks the existing OpenRouter step for prep, summary, and questions.
5. The workflow builds a Choosing-compatible day roster payload.
6. The workflow posts it to `https://speak.procterai.cc/v1/day_roster`.
7. The G2 plugin calls `/v1/client_candidate` and `/v1/question_cues` during the day, so the phone and glasses can suggest the current client and brief.

All date matching remains in `America/New_York`.

## n8nitro Import

Import:

```text
n8n/choosing-to-speak-simplepractice2-sync.json
```

A copy is also staged beside the existing planner workflow:

```text
/Users/jonathanprocter/Desktop/reMarkable n8n/choosing-to-speak-simplepractice2-sync.json
```

The workflow is a full duplicate of `remarkable-daily-planner-n8n.json` with one added normalizer node:

```text
Build Choosing to Speak Payload
```

The final node posts to:

```text
https://speak.procterai.cc/v1/day_roster
```

The normalizer converts the existing `Build Final Payload` output into `entries[]` with `clientName`, `start`, `end`, `prep`, `summary`, `bestQuestions`, and optional `previousSessionNotes`.

## Required n8nitro Env

The n8nitro workflow needs one Choosing to Speak bearer token available in its environment:

```text
CTS_BETA_TOKEN
```

Accepted aliases:

```text
CHOOSING_TO_SPEAK_BETA_TOKEN
VELVETSPEAK_BETA_TOKEN
```

Do not commit the token into any workflow JSON.

## Payload Shape

The workflow uploads:

```json
{
  "rosterDate": "2026-07-31",
  "lensId": "clinical",
  "source": "n8nitro-simplepractice-notion-sync",
  "replace": true,
  "entries": [
    {
      "eventId": "sp-...",
      "clientId": "client-...",
      "clientName": "Client Name",
      "start": "2026-07-31T10:00:00-04:00",
      "end": "2026-07-31T10:50:00-04:00",
      "summary": "AI prep summary",
      "prep": "Pre-session prep",
      "sessionPrep": "Pre-session prep",
      "bestQuestions": ["Question 1", "Question 2"],
      "previousSessionNotes": [
        {
          "sessionDate": "2026-07-24",
          "title": "Progress note",
          "summary": "Recent Notion note excerpt",
          "themes": ["Theme"],
          "goals": ["Goal"],
          "risks": ["Risk"],
          "nextSteps": ["Next step"]
        }
      ]
    }
  ]
}
```

The FastAPI planner source also now carries up to five recent Notion notes per matched client. The direct n8nitro duplicate uploads those fields if the workflow sends them, and otherwise uploads the prep, summary, and best questions already generated by the existing workflow. The Choosing backend stores client context in SQLite and caps any prior-note window to the five most recent entries.

## Local Webhook Fallback

The loaded local planner service on port `5555` was also patched with `POST /sync-choosing-to-speak`, but `planner.procterai.cc` currently resolves to a separate FastAPI surface that does not expose that route. The production n8nitro workflow should therefore use the direct `speak.procterai.cc` upload path above.
